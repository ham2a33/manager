# 1. Overview

AI Manager является SaaS-платформой.

На одном сервере одновременно работают сотни и тысячи компаний.

Каждая компания полностью изолирована.

Компания никогда не может получить доступ к данным другой компании.

Это обязательное требование архитектуры.

---

# 2. Tenant

Каждая компания является отдельным Tenant.

Пример

Tenant #1

Hayat Dental

----------------

Tenant #2

Like Clinic

----------------

Tenant #3

Rich Exchange

Все работают независимо.

---

# 3. Company ID

Каждая операция внутри системы обязана содержать Company ID.

Например

Получить диалог

↓

company_id = 15

↓

conversation_id = 347

Если Company ID отсутствует.

Запрос отклоняется.

---

# 4. Изоляция данных

Каждая таблица содержит company_id.

Например

Messages

company_id

Conversations

company_id

Clients

company_id

Knowledge

company_id

Leads

company_id

Settings

company_id

Строго запрещено выполнять запросы без фильтрации по company_id.

---

# 5. AI Isolation

AI никогда не использует знания другой компании.

Например

Hayat Dental

↓

вопрос клиента

↓

AI использует только документы Hayat Dental.

Документы Like Clinic никогда не рассматриваются.

---

# 6. Storage Isolation

Каждая компания имеет собственное файловое пространство.

Пример

storage/

company-15/

documents/

logos/

attachments/

company-22/

documents/

attachments/

Файлы не смешиваются.

---

# 7. Vector Database

Каждый Embedding содержит:

company_id

document_id

chunk_id

metadata

Поиск в Qdrant всегда фильтруется по company_id.

---

# 8. Cache Isolation

Все ключи Redis должны содержать Company ID.

Пример

company:15:conversation:347

company:22:ai-settings

company:15:knowledge

Это предотвращает смешивание данных.

---

# 9. Queue Isolation

Каждая задача содержит:

company_id

conversation_id

job_id

Даже фоновые задачи всегда знают, к какой компании относятся.

---

# 10. Logging

Каждый лог содержит:

company_id

user_id

event

timestamp

Это позволяет быстро находить ошибки конкретной компании.

---

# 11. Rate Limits

Ограничения применяются отдельно для каждой компании.

Например

Starter

500 сообщений в день

------------

Business

5000 сообщений

------------

Enterprise

Без ограничений

---

# 12. AI Usage

Для каждой компании считается отдельно:

Количество сообщений

Количество токенов

Стоимость

Используемые модели

Последняя активность

---

# 13. Security

Пользователь компании не может:

получить список компаний;

получить чужие документы;

получить чужие диалоги;

получить чужих клиентов;

получить чужие настройки.

Любая попытка фиксируется в Audit Log.

---

# 14. Roles

Минимальные роли MVP:

OWNER

Имеет полный доступ.

--------------

OPERATOR

Работает только с диалогами.

--------------

ADMIN

Управляет настройками компании.

---

# 15. Billing

Подписка хранится отдельно для каждой компании.

Например

Company #15

Business Plan

----------------

Company #22

Starter

Лимиты рассчитываются независимо.

---

# 16. Future Scaling

Архитектура должна позволять:

10 компаний

100 компаний

1000 компаний

10000 компаний

без изменения кода.

---

# 17. Rules

1. company_id обязателен почти во всех бизнес-сущностях.
2. Любой запрос фильтруется по company_id.
3. Поиск в Qdrant выполняется только внутри Tenant.
4. Redis использует company_id в ключах.
5. Очереди содержат company_id.
6. Все логи содержат company_id.
7. AI не имеет доступа к данным другой компании.
8. Файлы разделены по компаниям.
9. Каждая компания имеет собственные настройки AI.
10. Multi-Tenant является обязательным принципом всей платформы.
