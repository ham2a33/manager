# 1. Overview

Knowledge Base — это система хранения знаний компании.

AI никогда не отвечает, используя только свои знания.

Основной источник информации — Knowledge Base компании.

Каждая компания имеет собственную базу знаний.

Данные одной компании никогда не используются другой компанией.

# 6. Text Cleaning

Перед индексированием текст очищается.

Удаляются:

- пустые строки;
- повторяющиеся пробелы;
- служебные символы;
- колонтитулы;
- номера страниц;
- оглавление (если возможно).

---

# 7. Chunking

Текст разбивается на небольшие части.

Размер Chunk:

500–800 токенов.

Overlap:

50–100 токенов.

Chunk должен содержать законченную мысль.

Запрещается разрывать предложения посередине.

---

# 8. Embeddings

Для каждого Chunk создается Embedding.

Embedding хранится в Qdrant.

В PostgreSQL хранится только связь.

Каждый Embedding содержит:

- company_id
- document_id
- chunk_id
- metadata

---

# 9. Metadata

Каждый Chunk хранит:

Название документа

Номер страницы

Источник

Дата загрузки

Язык

Категорию

# 10. Search Flow

Поступает сообщение клиента.

↓

Создается Embedding запроса.

↓

Поиск в Qdrant.

↓

Получение Top-K результатов.

↓

Фильтрация.

↓

Передача Prompt Builder.

AI получает только найденные фрагменты.

---

# 11. Search Strategy

По умолчанию:

Top-K = 5

Минимальный Score:

0.75

Если результатов нет.

AI сообщает владельцу.

Не придумывает ответ.

---

# 17. Rules

1. Каждый документ принадлежит компании.

2. Embeddings разделяются по company_id.

3. Документы не смешиваются между компаниями.

4. Поиск выполняется только внутри компании.

5. AI никогда не использует документы другой компании.

6. Документы индексируются асинхронно.

7. Ошибки обработки не должны блокировать систему.

8. Старые версии документов можно восстановить (в будущих версиях).

9. Все изменения логируются.

10. Knowledge Base является единственным источником знаний компании.
