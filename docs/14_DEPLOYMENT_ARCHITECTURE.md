# 1. Overview

AI Manager должен быть полностью контейнеризирован.

Каждый компонент системы запускается как отдельный сервис.

Все сервисы взаимодействуют через внутреннюю Docker Network.

Архитектура должна одинаково работать:

- локально;
- на VPS;
- в облаке;
- в Kubernetes (в будущем).

# 3. Основные сервисы

MVP включает следующие контейнеры:

- nginx
- backend
- telegram-bot
- postgres
- redis
- qdrant
- minio
- worker
- scheduler

Каждый сервис имеет собственный контейнер.

---

# 4. Backend

Backend является центральным сервисом.

Он отвечает за:

- REST API
- Webhook
- AI Engine
- Business Logic
- Authentication

Backend не выполняет тяжелые фоновые задачи.

---

# 5. Telegram Bot

Telegram Bot запускается отдельно.

Он общается только с Backend API.

Бот не подключается к базе данных напрямую.

Все действия выполняются через REST API.

---

# 6. PostgreSQL

PostgreSQL хранит:

- компании;
- пользователей;
- сообщения;
- диалоги;
- лиды;
- настройки;
- статистику.

Является единственным источником структурированных данных.

---

# 7. Redis

Используется для:

- кэша;
- очередей;
- Rate Limit;
- FSM Telegram;
- временных данных.

Redis не хранит постоянную информацию.

---

# 8. Qdrant

Qdrant используется только для Vector Search.

Содержит:

- Embeddings;
- Metadata;
- Vector Index.

---

# 9. MinIO

Хранилище файлов.

Содержит:

- PDF;
- DOCX;
- изображения;
- голосовые;
- документы.

Backend хранит только ссылки.

---

# 10. Workers

Фоновые процессы.

Обрабатывают:

- PDF;
- DOCX;
- Embeddings;
- Retry;
- Summary;
- OCR (Future).

---

# 11. Scheduler

Запускает периодические задачи.

Например:

- обновление токенов;
- очистка временных файлов;
- создание статистики;
- архивирование.

---

# 12. Docker Network

Все контейнеры работают внутри одной приватной сети.

Внешний доступ имеют только:

- Nginx
- Backend API

Остальные сервисы доступны только внутри сети.

---

# 13. Reverse Proxy

Nginx отвечает за:

- HTTPS;
- SSL;
- проксирование;
- WebSocket;
- сжатие;
- лимиты запросов.

---

# 14. Environment Variables

Каждый сервис использует переменные окружения.

Например:

DATABASE_URL

REDIS_URL

QDRANT_URL

MINIO_URL

JWT_SECRET

OPENAI_API_KEY

META_APP_ID

META_APP_SECRET

Никаких секретов в коде.

---

# 15. Backup

Регулярно создаются резервные копии:

- PostgreSQL;
- MinIO;
- конфигурации.

Бэкапы могут храниться в отдельном облачном хранилище.

---

# 16. Monitoring

Система должна быть готова к интеграции с:

- Prometheus;
- Grafana;
- Sentry;
- Loki.

MVP может использовать только базовое логирование.

---

# 17. Масштабирование

При росте нагрузки можно масштабировать отдельно:

- Backend API;
- Workers;
- Telegram Bot.

PostgreSQL и Redis могут быть вынесены на отдельные серверы.

---

# 18. Production Requirements

Минимальная конфигурация:

CPU: 4 vCPU

RAM: 8 GB

SSD: 80 GB

Ubuntu LTS

Docker

Docker Compose

Для крупных клиентов требования увеличиваются в зависимости от нагрузки.

---

# 19. Deployment Pipeline

Этапы деплоя:

1. Получить новую версию кода.
2. Собрать Docker-образы.
3. Запустить миграции.
4. Проверить Health Check.
5. Обновить контейнеры.
6. Выполнить Smoke Tests.
7. Начать обработку трафика.

При ошибке должна быть возможность отката.

---

# 20. Основные правила

1. Каждый сервис работает в отдельном контейнере.
2. Backend не зависит от Telegram Bot.
3. Telegram Bot работает только через API.
4. Все секреты хранятся вне кода.
5. Все сервисы готовы к горизонтальному масштабированию.
6. Docker Compose используется для локальной разработки и MVP.
7. Kubernetes рассматривается как следующий этап развития.
8. Регулярные резервные копии обязательны.
9. Все сервисы должны иметь Health Check.
10. Архитектура должна позволять развернуть проект на любом облачном провайдере.
